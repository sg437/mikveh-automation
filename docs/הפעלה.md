# הפעלת המערכת – מדריך צעד אחר צעד

המסמך הזה הוא רשימת ההפעלה המלאה: מהעלאת הקוד לפרויקט ה-Apps Script ועד לקישור עובד
בטלפון. חמישה שלבים, כ-40 דקות. אחרי כל שלב יש **בדיקה** – אם היא עוברת, ממשיכים.

> הקוד של הוואטסאפ (V2) לא נפגע: הקבצים החדשים מצטרפים לאותו פרויקט Apps Script, והקולט
> של Green API ממשיך לעבוד בדיוק כמו היום.

## שלב 1 – העלאת הקוד לפרויקט ה-Apps Script

במחשב, בתיקיית הפרויקט – **להריץ `push.bat`** (או ידנית: `git pull` ואז `clasp push`).

⚠️ **לא להריץ כאן `sync.bat`.** הוא עובד בכיוון ההפוך: `clasp pull` מוריד מה-Apps Script
אל המחשב ואז דוחף ל-GitHub. הרצה שלו עכשיו תדרוס את `קוד.js` המעודכן בגרסה הישנה
שבסקריפט, ולא תעלה שום קובץ חדש. `sync.bat` נועד למקרה ההפוך – אחרי עריכה בעורך
ה-Apps Script, כדי להחזיר את השינוי ל-GitHub.

הקובץ `.claspignore` דואג שרק קבצי הסקריפט שבשורש יעלו. תיקיית `app/` **לא** עולה לסקריפט.

⚠️ `clasp push` מוחק מהפרויקט קבצים שאינם במחשב. אם ערכת משהו **בעורך ה-Apps Script**
מאז 10/07/2026 ולא הרצת `sync.bat` אחר כך – להריץ קודם `sync.bat` פעם אחת (כדי להחזיר
את העריכה ל-GitHub), ורק אז `push.bat`.

**בדיקה:** בעורך ה-Apps Script רואים את כל קבצי המערכת: `Api.js`, `ApiWrite.js`,
`Auth.js`, `Media.js`, `HebDate.js`, `WhatsappActions.js`, `Reminders.js`, `Projects.js`,
`WorkPoll.js`, `Questions.js`, ולצידם השלושה הקיימים: `קוד.js`, `Alerts.js`, `Reports.js`.

## שלב 2 – מאפייני הסקריפט (Script Properties)

בעורך: ⚙️ **Project Settings** ⟵ **Script Properties** ⟵ Add script property.

| שם המאפיין | ערך | חובה? |
|---|---|---|
| `MIKVAOT_SHEET_ID` | המזהה מתוך כתובת הגיליון: `docs.google.com/spreadsheets/d/`**`<כאן>`**`/edit` | **חובה** |
| `MIKVEH_ARCHIVE_FOLDER_ID` | המזהה של תיקיית הארכיון בדרייב (מתוך כתובת התיקייה) | חובה לתמונות |
| `GOOGLE_CLIENT_ID` | ראה שלב 4 | חובה לכניסה ותפקידים |
| `API_TOKEN` | סיסמה שתמציא (למשל 12 תווים אקראיים) | מומלץ |
| `WA_AUTO_ACTIONS` | `1` | כדי שדיווחי הוואטסאפ ייכנסו לתיק |
| `NOTIFY_WHATSAPP` | `1` | להתראות אישיות בוואטסאפ |
| `ALERT_CHAT_ID` | מזהה הקבוצה לתזכורות תעודה | לתזכורות |
| `WA_BRIDGE` | `1` = פתיחת משימות לחלוקה במערכת מודיעה גם לקבוצת הוואטסאפ (`GROUP_CHAT_ID`). דיווחים ודוחות פיקוח **אינם** נשלחים לקבוצה | רשות |
| `WA_WORK_POLL` | `1` = חלוקת העבודה נשלחת לקבוצה כ**סקר** (מקווה בכל שורה), וסימון בסקר רושם את המשימה על שם המסמן. דורש `GROUP_CHAT_ID` והרצה חד-פעמית של `installWorkPollTrigger` (סיכום "מי לקח מה") | רשות |
| `REQUIRE_LOGIN` | ברירת המחדל (בלי המאפיין): **כשמוגדר `GOOGLE_CLIENT_ID`, גם קריאת הנתונים מחייבת כניסה** – מי שפותח את הקישור בלי להיכנס רואה מסך כניסה בלבד. `0` מחזיר את ההתנהגות הישנה (כל מי שיש לו את הכתובת רואה הכל) – לא מומלץ | רשות |
| `WA_POLL_ANNOUNCE` | `0` = לא להודיע בקבוצה על כל לקיחה בסקר. הודעת "המשימה כבר נלקחה" נשלחת תמיד | רשות |
| `OPEN_SIGNUP` | `1` = כל חשבון Google נרשם לבד. **בלי המאפיין – רישום סגור**: רק מי שמנהל הוסיף מראש נכנס | רשות |
| `DEFAULT_ROLE` | `מפקח` / `קבלן` / `צופה` – מה מקבל מי שנרשם לבד (רק כש-`OPEN_SIGNUP=1`) | רשות |

המאפיינים הקיימים של Green API (`GREEN_ID_INSTANCE`, `GREEN_API_TOKEN`) נשארים כמו שהם.

**בדיקה:** מריצים בעורך את הפונקציה **`testApi`** (קובץ `Api.gs`) ופותחים את **יומן הביצוע**.
היא קוראת את הגיליון ומדפיסה את מספר המקוואות, מקווה לדוגמה, ודיווח הוואטסאפ האחרון.

> אין להריץ את `apiPing_` מהעורך – שם שמסתיים בקו תחתון הוא פונקציה פנימית,
> ו-Apps Script אינו מציג אותה בתפריט ההפעלה. היא נקראת דרך `?action=ping` בלבד.

## שלב 3 – פריסה (Deploy)

בעורך: **Deploy** ⟵ **Manage deployments** ⟵ ✏️ (עריכה) ⟵ Version: **New version** ⟵ Deploy.

חשוב שההגדרות יהיו:

- **Execute as:** Me (החשבון שלך)
- **Who has access:** **Anyone**

⚠️ לא ליצור פריסה חדשה מאפס אלא לעדכן את הקיימת – כך כתובת ה-Web App נשארת אותה כתובת
שרשומה ב-Webhook של Green API, והוואטסאפ ממשיך לעבוד.

מעתיקים את **Web app URL** (מסתיים ב-`/exec`).

**בדיקה:** פותחים בדפדפן `<הכתובת>?action=ping&token=<API_TOKEN>`. אמור לחזור JSON עם
`"ok": true` ורשימת הלשוניות עם `"found": true` לכל אחת.

**★ חובה, אחרת האפליקציה תיפתח לאט ★** — בעורך, ברשימת הפונקציות למעלה בוחרים
`installDataCacheTrigger` ולוחצים **Run** פעם אחת (מאשרים את ההרשאה אם נשאלים).
בניית הנתונים לאפליקציה קוראת 15 לשוניות ונמשכת כ-23 שניות; הטריגר הזה בונה
אותה **ברקע**, כל 5 דקות וכמה שניות אחרי כל דיווח, כך שבקשה של משתמש מקבלת
תמיד עותק מוכן. בלעדיו כל פתיחה שאחרי דיווח (גם דיווח שנקלט מהוואטסאפ)
מחכה לבנייה המלאה. `testDataTriggers` מדפיס אם הוא מותקן.

## שלב 4 – כניסה עם Google (Client ID)

ב-[Google Cloud Console](https://console.cloud.google.com/apis/credentials):

1. **OAuth consent screen** – External, שם האפליקציה "מערכת כשרות המקוואות", מייל תמיכה.
2. **Credentials** ⟵ Create credentials ⟵ **OAuth client ID** ⟵ **Web application**.
3. ב-**Authorized JavaScript origins** מוסיפים את כתובת האתר של האפליקציה (שלב 5),
   למשל `https://sg437.github.io` – רק הדומיין, בלי הנתיב.
4. מעתיקים את ה-**Client ID** (מסתיים ב-`.apps.googleusercontent.com`), ושמים אותו
   ב-Script Property `GOOGLE_CLIENT_ID` (שלב 2).

המשתמש הראשון שנכנס למערכת נרשם אוטומטית כ**מנהל** – כך אפשר להיכנס בפעם הראשונה.

מכאן והלאה, כברירת מחדל, **הרישום סגור**: מי שהמנהל לא הוסיף מראש במסך "משתמשים" יקבל
"אין לך הרשאה להיכנס למערכת" ולא ייווצר לו רישום כלל. כדי לפתוח רישום עצמי לכל אדם עם
חשבון Google – להוסיף `OPEN_SIGNUP=1` (ואז כדאי גם `DEFAULT_ROLE=צופה`, אחרת כל נכנס
חדש מקבל `מפקח` שרשאי לכתוב).

## שלב 5 – פרסום האפליקציה וחיבורה

### א. הקישור

בריפו יש Workflow שמפרסם את `app/` אוטומטית בכל דחיפה ל-main, אבל **לפני ההרצה הראשונה
צריך להפעיל את Pages ידנית פעם אחת**: **Settings** ⟵ **Pages** ⟵ Source: **GitHub Actions**.
(אי אפשר לעשות זאת מתוך ה-Workflow: ל-`GITHUB_TOKEN` אין הרשאה ליצור את אתר ה-Pages,
והוא נכשל ב-`Create Pages site failed: Resource not accessible by integration`.)

אחרי ההפעלה: **Actions** ⟵ "פרסום האפליקציה" ⟵ **Run workflow** (או כל דחיפה הבאה ל-main).

הקישור שמתקבל: `https://<שם המשתמש>.github.io/mikveh-automation/`

**בדיקה:** ב-**Actions**, ההרצה האחרונה של "פרסום האפליקציה" ירוקה (✓), והקישור נפתח.

(אפשר כמובן גם להעלות את תוכן `app/` לכל אחסון אחר – חייב להיות **https**, אחרת הדפדפן
לא ייתן גישה למצלמה ולמיקרופון.)

### ב. החיבור לגיליון – מתוך המערכת, בלי לגעת בקוד

נכנסים לקישור ⟵ **הגדרות והרשאות** ⟵ **חיבור לגיליון**:

1. מדביקים את כתובת ה-Web App (שלב 3).
2. אם הגדרת `API_TOKEN` – מדביקים אותו.
3. מדביקים את ה-Client ID (שלב 4).
4. **בדיקת חיבור ושמירה**.

המסך יציג טבלת מצב: איזה גיליון נמצא, כמה לשוניות אותרו, ומה מוגדר ומה עוד חסר.
ההגדרות נשמרות במכשיר, והכותרת תציג **"מחובר לגיליון"**.

> ההגדרה הזו נשמרת **במכשיר שעשה אותה בלבד**. מי שיקבל את הקישור לא יגדיר כלום —
> ולכן חשוב לעשות גם את שלב ג.

### ג. שכל מי שמקבל את הקישור יגיע למערכת המחוברת ★

**Settings ⟵ Secrets and variables ⟵ Actions ⟵ Variables ⟵ New repository variable:**

| שם המשתנה | ערך |
|---|---|
| `MIKVEH_API_URL` | כתובת ה-Web App מ-שלב 3 (מסתיימת ב-`/exec`) |
| `MIKVEH_API_TOKEN` | רק אם הגדרת `API_TOKEN` |
| `MIKVEH_GOOGLE_CLIENT_ID` | לא חובה – מגיע ממילא מהסקריפט |

הערכים נכנסים ל-`app/config.js` בזמן הפרסום (`tools/build_config.py`), וכך כל מי
שפותח את הקישור מגיע ישר למערכת המחוברת — ומשם למסך הכניסה.

⚠️ האתר ציבורי, ולכן גם הכתובת וגם הטוקן גלויים למי שפותח את קוד הדף. **הם אינם
ההגנה על הנתונים** — ההגנה היא הכניסה עם Google, שנאכפת בשרת: כשמוגדר
`GOOGLE_CLIENT_ID`, קריאת נתונים בלי סשן תקף מוחזרת בשגיאה, והאפליקציה מציגה
מסך כניסה בלבד (`REQUIRE_LOGIN` בטבלת המאפיינים).

**בדיקה:** לפתוח את הקישור בחלון גלישה בסתר — צריך לראות מסך כניסה, בלי נתונים,
בלי תפריט ובלי מסך ההגדרות.

### ד. התקנה בטלפון

בראש האפליקציה יש פס **"התקנת האפליקציה"**. לחיצה על "התקנה" פותחת את חלון
ההתקנה של הדפדפן, ואם אין כזה — מוסבר מה לעשות:

- **וואטסאפ**: קישור שנפתח מתוך וואטסאפ רץ בדפדפן הפנימי, ושם **אי אפשר להתקין**.
  ⋮ בפינה ⟵ **פתיחה בדפדפן**, ומשם להתקין.
- **אייפון (ספארי)**: כפתור השיתוף ⬆️ ⟵ **הוספה למסך הבית**.
- **אנדרואיד (כרום)**: ⋮ ⟵ **התקנת אפליקציה**.

לקיצור דרך לדיונים בלבד: אותו קישור עם `talk/` בסוף.

## שלב 5ה (מומלץ) – העלאה אוטומטית של הסקריפט

אחרי ההפעלה הראשונה אין צורך לחזור על שלב 1 ושלב 3 בכל תיקון. ה-Workflow
`.github/workflows/apps-script.yml` מריץ `clasp push` ומעדכן את הפריסה הקיימת
בכל דחיפה ל-main. הפעלה חד-פעמית, בשני סודות:

**Settings ⟵ Secrets and variables ⟵ Actions ⟵ New repository secret**

| שם הסוד | מאיפה לוקחים |
|---|---|
| `CLASPRC_JSON` | תוכן הקובץ `C:\Users\<המשתמש>\.clasprc.json` (נוצר ב-`clasp login`) |
| `CLASP_DEPLOYMENT_ID` | Deploy ⟵ Manage deployments ⟵ מזהה הפריסה הקיימת (`AKfycb...`) |

⚠️ `.clasprc.json` מכיל אסימון גישה לפרויקטי ה-Apps Script ולדרייב. יש להדביקו
**רק** בשדה הסוד של GitHub – סודות מוצפנים, אינם מופיעים ביומני ההרצה, ואינם
נחשפים ל-Pull Requests מריפו מפוצל. אין לשלוח אותו בצ'אט, במייל או בוואטסאפ.

**בדיקה:** Actions ⟵ "העלאת הסקריפט" ⟵ Run workflow ⟵ ההרצה ירוקה, ובעורך
ה-Apps Script מופיעה גרסה חדשה תחת Manage deployments.

> הפריסה הקיימת **מתעדכנת** ולא נוצרת חדשה, ולכן כתובת ה-Webhook של Green API
> נשארת זהה והקולט של הוואטסאפ אינו נפגע.

## שלב 6 (רשות) – תזכורות אוטומטיות וסקר חלוקת העבודה

בעורך ה-Apps Script מריצים פעם אחת את הפונקציה `installReminderTrigger` – היא מתקינה
טריגר שבועי ששולח לקבוצת ההתראות את רשימת התעודות שעומדות לפוג.

כשמפעילים `WA_WORK_POLL=1` מריצים פעם אחת גם את שתי הפונקציות האלה:

| פונקציה | למה |
|---|---|
| `setupWorkPollWebhooks` | מדליקה ב-Green API את ההתראות על סקרים (`pollMessageWebhook` וחבריו). **בלעדיה הסקר נשלח ונראה תקין בקבוצה, אבל שום סימון לא חוזר למערכת.** מפעילה מחדש את האינסטנס – דקה עד חמש דקות שבהן הודעות עלולות לא להיקלט |
| `installWorkPollTrigger` | טריגר כל 5 דקות ששולח לקבוצה את הודעת הסיכום ("מי לקח מה") אחרי שההצבעות נרגעות. בלעדיו הסימון עדיין נרשם כמשימה, רק הסיכום לא נשלח |

**שניים שסימנו את אותה שורה:** וואטסאפ אינו יודע לנעול אפשרות בסקר, ולכן שניהם
יכולים לסמן אותה — אבל המשימה נרשמת על הראשון בלבד. מיד עם הסימון השני נשלחת
לקבוצה הודעה: "כבר נלקח על ידי X, הסימון שלך לא נרשם", עם רשימת המקוואות
שעדיין פנויים. גם לקיחה מוכרזת מיד (`WA_POLL_ANNOUNCE=0` מכבה רק אותה).

**הודעת הסיכום** נשלחת פעם אחת לכל סקר: כשהכל חולק, או אחרי שלוש דקות שקט אם
נשארו פנויים. לקיחה נוספת אינה גוררת סיכום נוסף (הלקיחות ממילא מוכרזות מיד);
סיכום נוסף נשלח רק כשמשימה **משתחררת**, או כתזכורת אחרי שש שעות.

**כשמשהו לא עובד:** `testWorkPoll` מדפיס את הכל – מה מוגדר, אם הטריגר מותקן, מה מצב
כל סקר, ומה הגיע ביומן ההצבעות. לשונית **"יומן סקרים"** ריקה = ההתראות על סקרים
כבויות ב-Green API. `sendWorkPollSummaryNow` שולח סיכום מיד, בלי להמתין לשקט.

## שלב 6ב – הוספת הצוות: בקשות גישה

הרישום סגור, ולכן צריך להוסיף כל אחד. הדרך הקצרה: **לשלוח לקבוצה את הקישור
למערכת.** מי שפותח אותו רואה מסך כניסה; אחרי כניסה עם Google, מי שאינו רשום
מקבל חלון **בקשת גישה** וממלא שם מלא וטלפון (הכתובת מגיעה מגוגל ואינה
מוקלדת). אתה מקבל התראה בוואטסאפ, ומאשר במסך **משתמשים ➜ בקשות גישה**.

בכרטיס הבקשה מוצגים זה לצד זה, כדי שתוכל לזהות בוודאות מי זה:

| שדה | מאיפה |
|---|---|
| השם שהוזן | מה שהוא כתב על עצמו (ניתן לתיקון לפני האישור) |
| השם בוואטסאפ | הצלבה של הטלפון מול כל מי שאי פעם כתב בקבוצה |
| השם בחשבון Google | מה שרשום בחשבון שלו — לא תמיד מזהה אותו |
| אימייל | מגוגל, מאומת. זו הכתובת שאיתה ייכנס |

שמות שאינם תואמים מסומנים. באישור בוחרים תפקיד (מפקח / קבלן / צופה), המשתמש
נוצר, והוא מקבל הודעה בוואטסאפ שהגישה אושרה. דחייה אינה סופית — אפשר לבקש שוב.

עדיין אפשר גם להוסיף ידנית מראש (**משתמשים ➜ הוספת משתמש מראש**) כשהכתובת ידועה.

### לאסוף פרטים לפני שפותחים את המערכת

אם עוד לא רוצים לשלוח לקבוצה את הקישור למערכת: **הגדרות והרשאות ➜ טופס פרטים
לקבוצה ➜ שליחה לקבוצה**. נשלח כפתור לדף טופס קצר (שם, מייל, טלפון) שאינו
המערכת ואין ממנו גישה לשום נתון, וכל מילוי מופיע ב"בקשות גישה" לאישור.

- וואטסאפ אינו תמיד מציג כפתורים ממספר רגיל; כשזה קורה נשלחת הודעה עם הקישור,
  והמסך אומר לך מה נשלח בפועל.
- הטופס נפתח לקבלת מילויים בשליחה, ונסגר בכפתור "סגירת הטופס". כדאי לסגור
  כשסיימו.
- כתובת מייל שהוקלדה בטופס אינה מאומתת מול גוגל. מי שייכנס בסוף עם חשבון אחר
  יבקש גישה מתוך המערכת, וזו הדרך המדויקת.

## שלב 7 (רשות) – שאלה לקבוצת הוואטסאפ

במערכת ⇠ **הגדרות והרשאות** ⇠ **שאלה לקבוצת הוואטסאפ**: כותבים שאלה ("מה כתובת
המייל שלך?"), בוחרים סוג תשובה (אימייל / טלפון / תשובה חופשית) ושולחים. ההודעה
נשלחת לקבוצה, וכל תשובה נרשמת בלשונית **"תשובות מהקבוצה"** עם **השם והטלפון של
מי שכתב אותה** — ונשלחת התראה בוואטסאפ לשואל (וגם ל-`ALERT_CHAT_ID`, אם הוגדר).

- עונים ב**תשובה (Reply)** על הודעת השאלה. תשובה כזו נרשמת כתשובה בלבד ואינה
  נכנסת לתור הדיווחים.
- בשאלת **אימייל** או **טלפון** גם הודעה רגילה בקבוצה שיש בה כתובת או מספר
  נקלטת (כך אנשים עונים בפועל), והיא ממשיכה גם לתור הדיווחים כרגיל.
- שאלת אימייל גם **משלימה את הכתובת בלשונית "משתמשים"** למי שרשום שם לפי הטלפון
  ואין לו עדיין כתובת. מי שאינו רשום מסומן בטבלה כ"לא רשום במערכת".
- "סגירת השאלה" מפסיקה לקלוט אליה תשובות. שאלה נסגרת מאליה אחרי 60 יום.

דרישות: `GROUP_CHAT_ID` + Green API (אותם מאפיינים של הגשר). לבדיקה מהעורך:
`testAskGroup` — מדפיס מה מוגדר, אילו שאלות פתוחות ומה הגיע.

| שאלה לקבוצה (שלב 7) | התשובה נרשמת בלשונית "תשובות מהקבוצה" עם השם והטלפון, ומגיעה אליך התראה |
| כניסה עם חשבון Google שאינו רשום | נפתח חלון "בקשת גישה", ואחרי שליחה מגיעה אליך התראה בוואטסאפ והבקשה מופיעה במסך "משתמשים" |
| שליחת טופס הפרטים לקבוצה | בקבוצה מופיע כפתור (או הודעה עם קישור), והמילוי נוחת ב"בקשות גישה" |
