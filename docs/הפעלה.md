# הפעלת המערכת – מדריך צעד אחר צעד

המסמך הזה הוא רשימת ההפעלה המלאה: מהעלאת הקוד לפרויקט ה-Apps Script ועד לקישור עובד
בטלפון. חמישה שלבים, כ-40 דקות. אחרי כל שלב יש **בדיקה** – אם היא עוברת, ממשיכים.

> הקוד של הוואטסאפ (V2) לא נפגע: הקבצים החדשים מצטרפים לאותו פרויקט Apps Script, והקולט
> של Green API ממשיך לעבוד בדיוק כמו היום.

---

## שלב 1 – העלאת הקוד לפרויקט ה-Apps Script

במחשב, בתיקיית הפרויקט – **להריץ `push.bat`** (או ידנית: `git pull` ואז `clasp push`).

⚠️ **לא להריץ כאן `sync.bat`.** הוא עובד בכיוון ההפוך: `clasp pull` מוריד מה-Apps Script
אל המחשב ואז דוחף ל-GitHub. הרצה שלו עכשיו תדרוס את `קוד.js` המעודכן בגרסה הישנה
שבסקריפט, ולא תעלה שום קובץ חדש. `sync.bat` נועד למקרה ההפוך – אחרי עריכה בעורך
ה-Apps Script, כדי להחזיר את השינוי ל-GitHub.

הקובץ `.claspignore` דואג שרק קבצי הסקריפט שבשורש יעלו. תיקיית `app/` **לא** עולה לסקריפט.

⚠️ `clasp push` מוחק מהפרויקט קבצים שאינם במחשב. אם ערכת משהו **בעורך ה-Apps Script**
מאז 10/07/2026 ולא הרצת `sync.bat` אחר כך – להריץ קודם `sync.bat` פעם אחת (כדי להחזיר
את העריכה ל-GitHub), ורק אז `push.bat`.

**בדיקה:** בעורך ה-Apps Script רואים **עשרה** קבצים – השבעה החדשים: `Api.js`,
`ApiWrite.js`, `Auth.js`, `Media.js`, `HebDate.js`, `WhatsappActions.js`, `Reminders.js`,
ולצידם השלושה הקיימים: `קוד.js`, `Alerts.js`, `Reports.js`.

## שלב 2 – מאפייני הסקריפט (Script Properties)

בעורך: ⚙️ **Project Settings** ⟵ **Script Properties** ⟵ Add script property.

| שם המאפיין | ערך | חובה? |
|---|---|---|
| `MIKVAOT_SHEET_ID` | המזהה מתוך כתובת הגיליון: `docs.google.com/spreadsheets/d/`**`<כאן>`**`/edit` | **חובה** |
| `MIKVEH_ARCHIVE_FOLDER_ID` | המזהה של תיקיית הארכיון בדרייב (מתוך כתובת התיקייה) | חובה לתמונות |
| `GOOGLE_CLIENT_ID` | ראה שלב 4 | חובה לכניסה ותפקידים |
| `API_TOKEN` | סיסמה שתמציא (למשל 12 תווים אקראיים) | מומלץ |
| `WA_AUTO_ACTIONS` | `1` | כדי שדיווחי הוואטסאפ ייכנסו לתיק |
| `NOTIFY_WHATSAPP` | `1` | להתראות אישיות בוואטסאפ |
| `ALERT_CHAT_ID` | מזהה הקבוצה לתזכורות תעודה | לתזכורות |
| `WA_BRIDGE` | `1` = דיווחי פעולות ודוחות פיקוח שנרשמים במערכת נשלחים גם לקבוצת הוואטסאפ (`GROUP_CHAT_ID`), לתקופת המעבר | רשות |
| `OPEN_SIGNUP` | `1` = כל חשבון Google נרשם לבד. **בלי המאפיין – רישום סגור**: רק מי שמנהל הוסיף מראש נכנס | רשות |
| `DEFAULT_ROLE` | `מפקח` / `בלנית` / `צופה` – מה מקבל מי שנרשם לבד (רק כש-`OPEN_SIGNUP=1`) | רשות |

המאפיינים הקיימים של Green API (`GREEN_ID_INSTANCE`, `GREEN_API_TOKEN`) נשארים כמו שהם.

**בדיקה:** מריצים בעורך את הפונקציה **`testApi`** (קובץ `Api.gs`) ופותחים את **יומן הביצוע**.
היא קוראת את הגיליון ומדפיסה את מספר המקוואות, מקווה לדוגמה, ודיווח הוואטסאפ האחרון.

> אין להריץ את `apiPing_` מהעורך – שם שמסתיים בקו תחתון הוא פונקציה פנימית,
> ו-Apps Script אינו מציג אותה בתפריט ההפעלה. היא נקראת דרך `?action=ping` בלבד.

## שלב 3 – פריסה (Deploy)

בעורך: **Deploy** ⟵ **Manage deployments** ⟵ ✏️ (עריכה) ⟵ Version: **New version** ⟵ Deploy.

חשוב שההגדרות יהיו:

- **Execute as:** Me (החשבון שלך)
- **Who has access:** **Anyone**

⚠️ לא ליצור פריסה חדשה מאפס אלא לעדכן את הקיימת – כך כתובת ה-Web App נשארת אותה כתובת
שרשומה ב-Webhook של Green API, והוואטסאפ ממשיך לעבוד.

מעתיקים את **Web app URL** (מסתיים ב-`/exec`).

**בדיקה:** פותחים בדפדפן `<הכתובת>?action=ping&token=<API_TOKEN>`. אמור לחזור JSON עם
`"ok": true` ורשימת הלשוניות עם `"found": true` לכל אחת.

## שלב 4 – כניסה עם Google (Client ID)

ב-[Google Cloud Console](https://console.cloud.google.com/apis/credentials):

1. **OAuth consent screen** – External, שם האפליקציה "מערכת כשרות המקוואות", מייל תמיכה.
2. **Credentials** ⟵ Create credentials ⟵ **OAuth client ID** ⟵ **Web application**.
3. ב-**Authorized JavaScript origins** מוסיפים את כתובת האתר של האפליקציה (שלב 5),
   למשל `https://sg437.github.io` – רק הדומיין, בלי הנתיב.
4. מעתיקים את ה-**Client ID** (מסתיים ב-`.apps.googleusercontent.com`), ושמים אותו
   ב-Script Property `GOOGLE_CLIENT_ID` (שלב 2).

המשתמש הראשון שנכנס למערכת נרשם אוטומטית כ**מנהל** – כך אפשר להיכנס בפעם הראשונה.

מכאן והלאה, כברירת מחדל, **הרישום סגור**: מי שהמנהל לא הוסיף מראש במסך "משתמשים" יקבל
"אין לך הרשאה להיכנס למערכת" ולא ייווצר לו רישום כלל. כדי לפתוח רישום עצמי לכל אדם עם
חשבון Google – להוסיף `OPEN_SIGNUP=1` (ואז כדאי גם `DEFAULT_ROLE=צופה`, אחרת כל נכנס
חדש מקבל `מפקח` שרשאי לכתוב).

## שלב 5 – פרסום האפליקציה וחיבורה

### א. הקישור

בריפו יש Workflow שמפרסם את `app/` אוטומטית בכל דחיפה ל-main, אבל **לפני ההרצה הראשונה
צריך להפעיל את Pages ידנית פעם אחת**: **Settings** ⟵ **Pages** ⟵ Source: **GitHub Actions**.
(אי אפשר לעשות זאת מתוך ה-Workflow: ל-`GITHUB_TOKEN` אין הרשאה ליצור את אתר ה-Pages,
והוא נכשל ב-`Create Pages site failed: Resource not accessible by integration`.)

אחרי ההפעלה: **Actions** ⟵ "פרסום האפליקציה" ⟵ **Run workflow** (או כל דחיפה הבאה ל-main).

הקישור שמתקבל: `https://<שם המשתמש>.github.io/mikveh-automation/`

**בדיקה:** ב-**Actions**, ההרצה האחרונה של "פרסום האפליקציה" ירוקה (✓), והקישור נפתח.

(אפשר כמובן גם להעלות את תוכן `app/` לכל אחסון אחר – חייב להיות **https**, אחרת הדפדפן
לא ייתן גישה למצלמה ולמיקרופון.)

### ב. החיבור לגיליון – מתוך המערכת, בלי לגעת בקוד

נכנסים לקישור ⟵ **הגדרות והרשאות** ⟵ **חיבור לגיליון**:

1. מדביקים את כתובת ה-Web App (שלב 3).
2. אם הגדרת `API_TOKEN` – מדביקים אותו.
3. מדביקים את ה-Client ID (שלב 4).
4. **בדיקת חיבור ושמירה**.

המסך יציג טבלת מצב: איזה גיליון נמצא, כמה לשוניות אותרו, ומה מוגדר ומה עוד חסר.
ההגדרות נשמרות במכשיר, והכותרת תציג **"מחובר לגיליון"**.

> כדי שכל העובדים יקבלו את החיבור מוכן מראש ולא יגדירו כל אחד בנפרד – למלא את אותם
> שלושה ערכים בקובץ `app/config.js` ולדחוף ל-main. מי שכבר הגדיר במכשיר, ההגדרה שלו גוברת.

### ג. התקנה בטלפון

פותחים את הקישור בטלפון ⟵ תפריט הדפדפן ⟵ **הוספה למסך הבית**.
לקיצור דרך לדיונים בלבד: אותו קישור עם `?app=talk` בסוף.

## שלב 5ד (מומלץ) – העלאה אוטומטית של הסקריפט

אחרי ההפעלה הראשונה אין צורך לחזור על שלב 1 ושלב 3 בכל תיקון. ה-Workflow
`.github/workflows/apps-script.yml` מריץ `clasp push` ומעדכן את הפריסה הקיימת
בכל דחיפה ל-main. הפעלה חד-פעמית, בשני סודות:

**Settings ⟵ Secrets and variables ⟵ Actions ⟵ New repository secret**

| שם הסוד | מאיפה לוקחים |
|---|---|
| `CLASPRC_JSON` | תוכן הקובץ `C:\Users\<המשתמש>\.clasprc.json` (נוצר ב-`clasp login`) |
| `CLASP_DEPLOYMENT_ID` | Deploy ⟵ Manage deployments ⟵ מזהה הפריסה הקיימת (`AKfycb...`) |

⚠️ `.clasprc.json` מכיל אסימון גישה לפרויקטי ה-Apps Script ולדרייב. יש להדביקו
**רק** בשדה הסוד של GitHub – סודות מוצפנים, אינם מופיעים ביומני ההרצה, ואינם
נחשפים ל-Pull Requests מריפו מפוצל. אין לשלוח אותו בצ'אט, במייל או בוואטסאפ.

**בדיקה:** Actions ⟵ "העלאת הסקריפט" ⟵ Run workflow ⟵ ההרצה ירוקה, ובעורך
ה-Apps Script מופיעה גרסה חדשה תחת Manage deployments.

> הפריסה הקיימת **מתעדכנת** ולא נוצרת חדשה, ולכן כתובת ה-Webhook של Green API
> נשארת זהה והקולט של הוואטסאפ אינו נפגע.
